# M3 milestone report — Edge Ingestion and SQLite

Completed 2026-08-28. All eighteen M3 issues are implemented and verified. M4 remains READY and was not started.

## Runtime and MQTT ingestion

`edge-controller` owns named MQTT, persistence-pipeline, retention, metrics, and shutdown tasks. A panic or unexpected task exit fails the supervisor; shutdown stops ingress and drains workers to a bounded transaction boundary.

The Edge subscribes at QoS 1 to exactly:

```text
rhizo/v1/devices/+/status
rhizo/v1/devices/+/telemetry
rhizo/v1/devices/+/actuator
rhizo/v1/devices/+/commands/result
rhizo/v1/devices/+/events
```

All five subscriptions are requested after every CONNACK. The bounded ingress channel applies backpressure. The real-broker suite proves ingestion resumes after a Mosquitto restart.

The shared MQTT contract performs envelope, version, kind, and topic/payload identity validation. The injected Edge `Clock` supplies authoritative `received_at`; device time is retained only as advisory metadata.

## SQLite and transactions

Migration `0001_initial.sql` establishes the ADR-004 tables plus M3 transport tables for actuator states, command results, and replay progress. Post-M3 correction `0002_late_replay_effect_identity.sql` adds stable per-sample telemetry effect identity. SQLite runs in WAL mode with foreign keys, NORMAL synchronous mode, a 5-second busy timeout, and a four-connection bound. Required measurement, time, batch, dedup, and replay indexes are present. SQLx offline metadata is checked by CI.

Every message is processed in one transaction: insert the unique message marker, write all accepted effects and outbox state, then commit. A duplicate rolls back and is a normal no-op. Deterministic rollback tests prove there is no durable marker without its effects. SQLite busy failures use three bounded full-jitter retries before failing the message unprocessed.

## Typed telemetry and replay

Each `telemetry.batch` creates narrow typed sample rows. Shared contract validation nulls only an invalid sample's value, retains valid siblings, and records `sensor_invalid`. Unknown forward-compatible kinds remain advisory data. Actuator state remains in its own table.

Replay preserves `event_id`, `boot_id`, `device_seq`, occurrence metadata, and Edge receipt time. Event and message identities both deduplicate. History gaps are durable first-class rows. The cumulative non-retained `event.ack` is published only after commit and advances only through the highest contiguous committed sequence. A lost ACK therefore causes safe replay rather than duplicate history.

## Quarantine, retention, and observability

Malformed messages are stored with topic, bounded diagnostic error, and at most the first 1 KiB of payload. Storage is capped at 1,000 rows and admission is limited to 10 rows per device per minute; decode counters still count suppressed entries.

Retention deletes eligible processed-message markers after 7 days only where the effect has independent stable uniqueness. Status markers remain because retained status and fixed LWT payloads can be redelivered indefinitely. Synced outbox rows are deleted after 24 hours, measurements after 90 days, and excess quarantine rows in bounded batches. Commands, watering events, device events, and history gaps are never pruned by M3.

### Post-M3 dedup-retention correction

The pre-M4 audit found that telemetry depended solely on the seven-day transport marker, while actuator and command-result uniqueness surfaced a late duplicate as a constraint error. Telemetry rows now use `(device_id, batch_id, sample_index)` uniqueness so a resealed batch remains one sampling effect; command results use stable `command_id`; actuator paths detect existing `message_id` effects before touching device state; replay detects stable `event_id` sets. A follow-up status audit confirmed that legitimate heartbeats use fresh message ids, so status now uses a bounded per-device `(boot_generation, sequence, current-LWT-id)` high-water projection and all transport markers are prunable. Regression tests remove markers and exercise exact and application-level replays, asserting one logical effect and unchanged current-device timestamps.

Ingestion metrics use constants from `rhizo-telemetry` and bounded labels for message kind, outcome, validation class, task, and gap tier. A cardinality guard keeps the registered series below 100 and rejects device identity labels.

## Negative controls

- Replacing Edge receipt time with `device_time_ms` failed the timestamp-authority test (`1756121400000` versus `42000`). Reverted.
- Rejecting an entire mixed-validity batch failed the sibling-preservation test (`New, 0` versus `New, 1`). Reverted.
- Suppressing the explicit reconnect subscription was exercised against a broker restart. Rumqttc's internal request replay kept the black-box test green; explicit per-CONNACK subscription remains in production so recovery does not rely on that client implementation detail.

## Deviations from plan

The accepted ADR schema requires a plant identifier on watering rows, while M3 can receive autonomous watering history before M5 plant binding exists. M3 therefore permits a null `plant_id` only for transported offline history; no binding or irrigation decision is inferred. M5/M6 retain ownership of interpretation.

## Boundary and next issue

No registry REST endpoint, health timer, plant binding, recommendation, watering command, irrigation state machine, offline evaluator, or cloud sync was added. The dependency graph identifies **M4-001 — status ingestion** as the next executable issue.
