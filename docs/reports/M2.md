# M2 milestone report — Device Simulator

Completed 2026-08-27. All nineteen M2 issues implemented, their acceptance
criteria ticked against demonstrated behaviour, and the full project gate green
on Rust 1.98.0 against a real Mosquitto. M3 was not started.

## What was built

A host binary that behaves like an ESP32 plant node: it speaks exactly MQTT v1,
models soil and water plausibly, injects thirteen faults on demand, and runs on
accelerated virtual time. It is the component that makes M3–M8 achievable
without hardware, and it is the reference implementation of the device side of
the protocol.

The requirement everything else rests on — **the simulator is never more
permissive than the firmware** — is enforced structurally rather than asserted.

## The three structural properties

Each is a test over the crate's own source, because each is a property of the
code's *shape* rather than of any single execution
(`tests/single_actuation_path.rs`).

| Property | How it is checked |
|---|---|
| One actuation path | Exactly one **call expression** of `validate_water_command`, and it is in `command.rs` |
| One way to move the pump | Exactly one call site of `start_pump`, in the gate's accept arm |
| No bypass | `force_water`, `debug_water`, `raw_pump`, `test_bypass`, `unsafe_actuate`, `allow_any_dose`, `skip_validation`, `bypass_gate` appear nowhere |
| No offline evaluator | No `evaluate_offline` call, no `OfflineDecision`, no `RefuseReason`, no dose scheduler — *and* the `offline_seam` M6-019 connects does exist |
| One clock | No `Utc::now` at all; the only `Instant::now` outside `clock.rs` is the MQTT shutdown drain, a network timeout that must stay real |
| The test hook is unreachable | `store_mut_for_test` has no call site in `src`, and is behind a feature the shipped binary does not enable |

The scanner has its own test (`the_scanner_actually_reads_the_sources`): an
empty file list or a comment filter that swallowed the file would otherwise read
as "no violations".

### Two documented greps were corrected

Both `grep -c validate_water_command` (M2-008) and
`grep 'evaluate_offline' && exit 1` (M2-017) count **documentation**. The first
matches a `use` statement and five doc comments; the second matches six doc
comments that explain the M2/M6 boundary. Exiting non-zero on those would mean a
codebase that cannot describe its own safety properties. The call-expression
forms, and the structural tests, check what the criteria mean.

## MQTT behaviour

**Subscriptions**, re-established on *every* connect from
`Topic::device_subscriptions`, so a reconnect restores exactly these four rather
than whichever subset a call site remembered:

```text
rhizo/v1/devices/{id}/config
rhizo/v1/devices/{id}/policy
rhizo/v1/devices/{id}/time
rhizo/v1/devices/{id}/commands/+
```

**Publications**, all QoS 1:

| Topic | When | Retained |
|---|---|---|
| `status` | connect, config change, policy activation, clock-sync transition, heartbeat every 5 × interval, and at most every 60 s while unsynchronised | **yes** |
| `telemetry` | one `telemetry.batch` per sampling cycle, plus an immediate cycle on a leak change | no |
| `actuator` | on change only, never periodically | no |
| `commands/result` | every command, including rejections; persisted and republished after a reconnect or a reboot | no |
| `events` | on every reconnection, in `device_seq` order, batches of 32, `complete: true` on the last | no |

**Retention is derived, not chosen.** `Publication::new` takes the retain flag
from `Topic::metadata`, so no call site has a parameter to get wrong. The
matrix is verified after a full command cycle by a fresh subscriber
(`retained_topics_are_exactly_status_config_and_policy`), and both negative
controls were run and reverted.

**Connection**: `clean_session = true`, client id = `device_id`, keepalive 60 s,
LWT configured on the options **before** `AsyncClient::new`, reconnect with
full-jitter backoff base 2 s cap 300 s, unlimited.

## Simulator physics

Deterministic from `--seed`; noise on by default.

```text
soil     dVWC/dt = -k · (VWC − VWC_floor) · temp_factor(T)
         k 0.06/h, floor 8.0 %, temp_factor = max(0.5, 1 + 0.03·(T − 21))
absorb   pending pool, 63 % transferred within absorption_tau (6 min)
         ΔVWC = 100 · ml / (pot_volume_ml · soil_factor)
overshoot  +15 % of the absorbed change, decaying with tau 2 min
drainage   volume beyond field_capacity 45 % is lost at delivery, and so
           never reaches the scale either
weight   dry_weight + water_g; water_g += delivered_ml IMMEDIATELY,
         −6 g/h evapotranspiration; `stable` false for 30 s after a change
tank     depletes by exactly the delivered volume, never negative
ec       base_ec · (reference_vwc / vwc) + fertilisation, decaying 5 %/h
noise    Gaussian σ: VWC 0.3, °C 0.1, g 2.0, tank 0.5 %, EC 15 µS/cm
```

The key relationship holds and is asserted directly
(`weight_rises_immediately_while_moisture_still_lags`): the scale reads 80 g
heavier the instant water is delivered, while VWC has not moved at all and is
still absorbing a time constant later.

**Two generators, deliberately separate.** The model generator is seeded from
`--seed`, so a physics run is reproducible. The identity generator is seeded
from the OS, because reproducible `message_id` values would be deduplicated away
by the edge after a restart and the telemetry would vanish silently.

## Time

One clock per process. `--time-scale` scales the **monotonic** clock; wall time
is the last applied `edge.time` plus that elapsed, so published timestamps stay
plausible UTC values anchored to a real Edge instant while running fast.

A tick's virtual time is applied to the models in steps of at most one virtual
second, so the drying curve, the absorption pool, and the overshoot decay evolve
identically at every scale — otherwise an accelerated test would be exercising
something other than the system.

**A full dose, absorption wait, and recheck completes in 1.4 s of wall time at
`--time-scale 600`** (`a_full_cycle_completes_in_under_ten_seconds_at_scale_six_hundred`).

## Time synchronisation

| Received `edge.time` | Effect |
|---|---|
| First valid `T` | applied; `clock_synced` true; status announces the transition |
| Duplicate `T` | ignored **entirely** — the clock does not move and the freshness anchor is **not** refreshed |
| Older `T − 1` | ignored; the clock never moves backwards |
| Newer `T + 1` | applied; the validity window restarts |
| Age ≥ 1800 s | `clock_synced` false; `device_time_ms` omitted; `message_id` reverts to UUIDv4 |
| Reconnect | still unsynchronised; commands refused with `clock_unsynced` until a fresh sync |

A captured message replayed forever therefore cannot hold `clock_synced` alive —
the property SAFETY-002 depends on, tested across the whole validity window.

## Persistent state

An NVS-equivalent JSON file, written atomically (temp file → `sync_all` →
rename). It holds: boot count, applied config version, daily total and its day
epoch, the 16-entry command ring with outcomes, the in-flight dose, pending
results, active and staging policy with checksums, applied policy versions, the
offline runtime state, and the bounded event buffer with its gap and
acknowledgement metadata.

**Corruption fails closed.** A corrupt or unreadable file sets an observable
persistent-state fault: the device starts, keeps sensing and reporting, and
**refuses every dose**. It never clears deduplication uncertainty, replenishes a
budget, shortens a cooldown, or substitutes a policy — and the lockout survives
the next restart, because the fault itself is persisted. The unreadable file is
moved aside rather than overwritten, so the evidence survives.

### The whole file is checksummed, not only the policy blob

A property test found the case ADR-015's policy CRC does not cover: JSON with
one flipped digit is still valid JSON, so `delivered_today_ml: 460.0` silently
becoming `60.0` would decode cleanly and hand the device four hundred
millilitres of budget it had already spent. The file therefore carries a
checksum over its whole contents. It covers the *decoded* state rather than the
raw bytes, so a field a future build adds is still ignored rather than treated
as damage. Recorded in PRD 020 §Data model.

## Command safety

```text
decode → persistent-state fault? → pump busy? → shared gate
       → persist in-flight → actuate → deliver → result
```

- **Dedup**: the same `command_id` actuates once and produces a result every
  time, including across a restart — the ring is persisted. A repeat arriving
  *during* a dose is refused `pump_unavailable`, because the outcome is not in
  the ring until the run ends.
- **Persist before actuate**: `(command_id, started_at, requested_ml)` reaches
  the store before the pump is energised (protocol §5.8 step 13).
- **Interruption**: a restart mid-dose reports `status: "interrupted"` with
  `delivered_ml: null` and credits the **full requested volume** to the daily
  total, because a device that cannot know what it delivered must assume the
  worst. The command is then in the ring, so a redelivery is deduplicated
  rather than run.
- **Results are ledger data**: persisted before publication, republished after a
  reconnect and after a reboot.
- **Calibration goes through the same gate**, converted to the volume it would
  deliver. See Deviations.

`safety_007_simulator_refuses_like_hardware` publishes `requested_ml: 10000`
directly to the broker, bypassing any edge, and asserts on the reservoir as well
as the reported number: 80 ml left the tank, the run was 9757 ms, and
`clamped: true`.

## Offline mechanics

**Implemented in M2:**

- policy validate → stage → verify → activate → acknowledge, with the read-back
  verification performed **from disk**
- per-plant version monotonicity, and per-plant merge (an omitted plant retains
  its policy)
- rejection against declared capabilities: undeclared actuator, unproducible
  measurement
- persisted monotonic runtime state: cycle phase, budget window, cooldown
  remaining, confirmation elapsed, dose count
- isolation detection, `connectivity` in status, and continued sampling,
  buffering, and physical evolution while alone
- the bounded event buffer, replay, and gap reporting
- `Device::offline_seam(plant_id)` — the single integration seam, returning
  exactly the four arguments `rhizo_policy::evaluate_offline` takes

**Not implemented in M2, deliberately:**

- policy evaluation
- autonomous watering, and any autonomous dose scheduler

An enabled, valid, activated policy is **inert**. Two days of simulated time on
a bone-dry isolated plant with ideal dosing conditions moves not one millilitre
(`an_isolated_device_with_an_enabled_policy_never_waters_in_m2`).

### SAFETY-019, at every step

`--fault policy-interrupt:<step>` kills the device after each of the five steps.
For all five, a reload from disk finds **exactly one** valid active policy whose
checksum matches and whose version equals the acknowledged one: the previous
policy after `validate`, `stage`, and `verify`; the new one after `activate` and
`acknowledge`. Stated as two tests, so a regression that made every step keep
the old policy would be visible rather than silently satisfying the property.

## Event replay

| | |
|---|---|
| Audit capacity | 64, never evicted to make room for telemetry |
| Telemetry capacity | 256 |
| Replay batch | 32 events, `complete: true` on the last only |
| Empty buffer | still one complete batch — the edge holds the plant in `Uncertain` until it sees the flag |

`event_id` is drawn **once**, at buffering time, and reused by every replay and
across restarts. Replaying three times yields ten distinct ids counted three
times each, not thirty events. Eviction records one gap marker spanning the run,
with its own stable id, replayed as a `history.gap` audit event carrying the
lost range, count, and tier; losing audit history upgrades the reported tier.

Real M2 events are produced, so the buffer is not vacuous: `policy.activated` on
activation, and `lockout.set` when a persistent-state fault is found at boot.

## Faults

All thirteen from simulator-strategy §6, plus `policy-interrupt:<step>` for
M2-016 — settable at startup and at runtime, composing, and each with a test
asserting its observable effect (`tests/faults.rs`).

```text
disconnect:<sec>      real isolation: socket dropped, sampling continues
duplicate:<rate>      republished with an IDENTICAL message_id
reorder:<rate>        delayed past the next; never dropped
invalid-soil:<rate>   out-of-range or null+fault; never a non-finite number
stuck-sensor          bit-identical readings; reversible
clock-unsync          every water command refused
clock-skew:<sec>      offsets both the published timestamp and the expiry check
leak / tank-empty     assert the sensor / empty the reservoir
pump-no-delivery      pump runs, tank and scale do not move
pump-stuck-on         the independent run guard stops it; reported `failed`
restart               one reboot, then disables itself
restart-mid-dose      dies after the state write, with the pump energised
policy-interrupt:<s>  dies at a chosen activation step
```

`no_fault_can_cause_a_dose` runs every fault for a simulated day and asserts the
pump never starts and no water moves. `every_fault_in_the_catalogue_has_a_test_here`
keeps the catalogue and the test file from drifting apart.

## Negative controls

Each mutation was applied, the failure observed, and the mutation reverted.

| Mutation | Caught by |
|---|---|
| Corrupt state file "starts fresh" | `safety_012_corruption_never_makes_the_device_more_permissive` — **and it did not, the first time**: the property had an early return that let a permissive reset through. The property was rewritten as a single implication and the control re-run. |
| `edge.time` published retained | `retained_topics…` — *"time was retained"* |
| Water command published retained | `retained_topics…` — *"commands/water was retained"* |
| ACL file emptied | both ACL tests, on their positive assertions |
| ACL pattern widened to `rhizo/v1/#` | both ACL tests, on the isolation assertions precisely |
| `event_id` regenerated on replay | six tests across two suites |
| A corpus path removed | `a_deliberately_added_field_is_detected` |

The retained-`edge.time` control also demonstrated the operational point: the
retained message **persisted in the broker** and poisoned every later run until
it was deleted. `clear_device_retained` now clears every edge→device topic, so a
single bad run cannot leave the suite permanently red.

## Bugs this work found

- **A fail-open in the tare freshness check.** Reading the clock with `?` and
  propagating its absence returned "no refusal" for a device with no clock at
  all. Caught by `a_tare_with_an_unsynchronised_clock_is_refused`.
- **A hole in the fail-closed property test**, above.
- **The state file had no integrity check**, above.
- **A duplicate command arriving mid-dose would have restarted the pump**: the
  outcome is not in the dedup ring until the run ends. Now refused.
- **`restart` rebuilt the plant as well as the device.** A reboot must not reset
  the soil and the reservoir — that would hide every consequence of the dose
  that was interrupted.
- **A control-API restart left the old socket**, so the restarted device kept
  the previous will and never published again.
- **A clean shutdown could fire the will**: `publish` and `disconnect` only
  queue requests, so returning before the event loop wrote them dropped the
  socket and the broker published `connection_lost` over the retained
  `shutdown`.
- **The result reported the clamped volume as `requested_ml`**, hiding the
  clamp the edge needs to see.

## Deviations from the issues, and why

1. **The fixture-drift check is Rust, not `tools/check_fixture_drift.py`**
   (M2-011). Same reason `rhizo-docscheck` is Rust: it runs inside `cargo test`
   with no second toolchain in CI, and it cannot drift from the capture code it
   checks. `--capture-fixtures` is unchanged.
2. **`command.calibrate` is subject to the full gate**, not a subset (M2-008).
   A subset needs a second validation path, which §5.8 forbids. Stricter, never
   more permissive; recorded in the protocol.
3. **The control API is not feature-gated** (M2-009). `--no-control-api`
   disables it at runtime instead. A feature gate would produce two builds of
   the reference device, and a scenario suite run against the gated-out build
   would lose fault injection silently.
4. **Two documented greps were corrected**, above.

## Known limitations

- **No acknowledgement mechanism exists in v1**, so buffered events are replayed
  on every reconnection until M6-020 adds one. Bandwidth, not correctness: the
  edge deduplicates on `event_id`.
- **`--scenario <file.yaml>` is parsed but not implemented.** The flag is
  defined so the interface is stable; scripted scenarios are M8's.
- **A device with no leak sensor cannot water at all**, because the shared gate
  refuses `LeakState::Unknown`. That is the contract's fail-closed decision, not
  the simulator's, and it is worth knowing before configuring `--sensors`.
- **The physical model is an approximation**, as PRD 020 §Non-goals says. The
  defaults for `absorption_tau` and `field_capacity_vwc` are plausible starting
  values, refined against real observations in M10-010.
- **Broker-backed tests are serialised** by a lock, because `.env` provides two
  device accounts and every test drives `plant-node-01`. They add about 60 s to
  a full run.
- **The `duplicate` and `reorder` faults are applied at the driver**, so the
  device core's own tests do not see them. They are covered as a pure pipeline
  instead.
