## Delivered

The whole software system — Mosquitto, the device simulator, the edge
controller, the cloud API, and PostgreSQL — starts from one `docker compose up
--build`, and the complete scenario suite runs against an accelerated copy of it
from one `./scripts/run-scenarios.sh`.

Three multi-stage Dockerfiles build the services with `cargo chef` dependency
caching onto `debian:bookworm-slim`, each running as uid 10001 with the binary
as PID 1, so `docker compose stop` delivers SIGTERM to the process and the
graceful-shutdown path runs. Health gating is by HTTP against what each service
is actually serving.

`deploy/docker-compose.test.yml` overlays an accelerated topology: every service
has `restart: "no"` so a crash fails the run instead of being papered over, the
edge and both simulators take one `RHIZO_TIME_SCALE`, and the edge image is
built separately with the `e2e-faults` feature that compiles in the two
process-boundary crash hooks SCEN-051 and SCEN-102 need.

`rhizo-scenarios` is a Rust binary with a typed harness: an edge REST client, a
simulator control client, direct SQLite and PostgreSQL readers, an MQTT spy
subscribed to `rhizo/v1/#`, Docker lifecycle control, per-scenario database
reset, and a failure dump of database rows, captured MQTT, simulator state, and
container logs. Forty scenarios cover the baseline, MQTT and device failures,
lockouts, restarts, cloud independence, isolation, reconciliation, battery and
sleep, and the eighteen-step first demo.

Three startup checks run before the first scenario and end the run on failure:
time-scale agreement across edge, simulator, and runner; that the edge under
test can actually be crashed at an exact instant; and that each device
authenticates as itself rather than as the edge principal.
