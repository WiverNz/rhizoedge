# M4 — Device Registry and Health

**Status:** DONE — 2026-08-28. M4-001 through M4-013 and the milestone exit gate were demonstrated.

## Delivered

- M3's single MQTT ingress/decoder remains the only transport path. Its durable status-order outcome gates registry projection; duplicates and logically old status cannot refresh `last_seen_at` or regress state.
- Every valid status receipt independently publishes live QoS 1, non-retained `edge.time`. A real-Mosquitto fresh-subscriber check proves it is not retained. The liveness timer refreshes online devices every 300 seconds.
- Registry rows hold lifecycle, firmware/protocol, boot, clock, config, resource, sensor, declared-capability, and advisory-connectivity state. Auto-registration records `device_registered` and creates no plant.
- LWT applies offline once, freezes `last_seen_at`, distinguishes `connection_lost` from `shutdown`, and records the transition. Boot changes are events/counters; rapid alternation raises `boot_id_thrash`.
- Staleness is derived from Edge `received_at` as `max(15 minutes, 3 × telemetry interval)`. A supervised timer detects silence without inbound traffic, emits stale/drift events, updates lifecycle gauges, and maintains time sync.
- Sensor presence/health/errors, row-based capabilities, capability changes, drift, isolation periods, and connected/isolated/reconciling state are exposed without assuming hardware.
- Axum serves health, metrics, device list/detail/name patch/events, and quarantine endpoints. It uses loopback by default, exact-origin CORS, bounded bodies/time, consistent errors, immutable device IDs, RFC 3339 timestamps, and bounded route/status metrics.
- Readiness requires MQTT `Subscribed`, tolerates one reconnect backoff, reports the pre-M6 control loop as `not_applicable`, and excludes cloud reachability.

## Verification

The full formatting, clippy, all-features test, required real-broker test, embedded cross-build, SQLx prepare, Compose config, docscheck, and diff gates passed. The sandboxed broker run's Docker restart was denied by the host WSL service; the exact unchanged test passed with host Docker permission. No required broker test skipped.

The running binary returned 200 with `mqtt: subscribed`, then 503 with `mqtt: disconnected` after Mosquitto was stopped, and returned to service after the broker was restored. The current M4 Compose file has no `cloud-api` service (M7 owns it), so the literal `docker compose stop cloud-api` command is not applicable; the cloud-absent runtime returned 200 and the isolated health test proves cloud is not a readiness check.

Issue-level filters covered status, registration, staleness, sensors, drift, health/API/CORS, metrics, capabilities, connectivity, retained status, LWT, no-plant registration, and timer-only stale detection. Existing M0–M3 and simulator safety suites stayed green.

Negative control: temporarily removing the 15-minute staleness floor made `device::health::staleness::floor_and_interval` fail (`30` versus `900` seconds); the mutation was reverted and the test returned green.

## Boundaries

M4 adds no watering, recommendation, plant automation, offline evaluator, reconciliation executor, or configuration publisher. V1 REST authentication remains intentionally absent; loopback/default binding is the security boundary. The pre-M6 control-loop health check remains `not_applicable`.
