# M4 — Device Registry and Health

**Status:** DONE — 2026-08-28. M4-001 through M4-013 and the milestone exit gate were demonstrated.

## Delivered

- M3's single MQTT ingress/decoder remains the only transport path. Its durable status-order outcome gates registry projection; duplicates and logically old status cannot refresh `last_seen_at` or regress state.
- Every valid status receipt independently publishes live QoS 1, non-retained `edge.time`. A real-Mosquitto fresh-subscriber check proves it is not retained. The liveness timer refreshes online devices every 300 seconds.
- Registry rows hold lifecycle, firmware/protocol, boot, clock, config, resource, sensor, declared-capability, and advisory-connectivity state. Auto-registration records `device_registered` and creates no plant.
- LWT applies offline once, freezes `last_seen_at`, distinguishes `connection_lost` from `shutdown`, and records the transition. Boot changes are events/counters; rapid alternation raises `boot_id_thrash`.
- Staleness is derived from Edge `received_at` as `max(15 minutes, 3 × telemetry interval)`. A supervised timer detects silence without inbound traffic, emits stale/drift events, updates lifecycle gauges, and maintains time sync.
- Sensor presence/health/errors, row-based capabilities, capability changes, drift, isolation periods, and connected/isolated/reconciling state are exposed without assuming hardware.
- Axum serves health, metrics, device list/detail/name patch/events, and quarantine endpoints. It uses loopback by default, exact-origin CORS, bounded bodies/time, consistent errors, immutable device IDs, RFC 3339 timestamps, and bounded route/status metrics.
- Readiness requires MQTT `Subscribed`, tolerates one reconnect backoff, reports the pre-M6 control loop as `not_applicable`, and excludes cloud reachability.

## Post-M4 battery-compatibility correction — 2026-08-28

After the original M4 gate completed, the registry/health model was corrected
before M5 started so an intentionally sleeping battery device is not presented
as an ordinary failure. This is a dated correction, not a claim that the
original M4 implementation already contained battery support.

The additive MQTT v1 change is deliberately small: `device.status.data.power`
may declare `mode`, relative `wake_interval_seconds`, and diagnostic
`expected_wake_ms`, `wake_reason`, `battery_mv`, and `awake_ms`. Absence or an
unknown mode resolves to `always_on`. A sleep announcement is the existing
retained QoS 1 offline status with `reason: "sleeping"`; it is valid only with
declared battery mode and a 60–86400 second relative interval. No topic,
subscription, retention rule, consumer, decoder, or status-order path was
added. The device timestamp remains diagnostic and never drives liveness.

The complete internal state model is `Online`,
`SleepingExpected { expected_until }`, `OfflineUnexpectedly`, and
`Reconciling`. The established REST vocabulary maps these to `connected`,
`sleeping`, `isolated`, and `reconciling`. Edge computes
`expected_wake_at = received_at + wake_interval_seconds` and
`overdue_at = expected_wake_at + max(wake_interval_seconds, 300 seconds)`.
An accepted sleep does not refresh `last_seen_at` and emits `device_slept`, not
an offline-failure event. A timer-only missed deadline transitions to isolated,
increments `missed_wake_count`, and emits `device_wake_missed`. A newer wake
returns online, clears the window/count, and emits `device_woke`. M3's persisted
boot-generation/status-sequence decision remains the sole ordering authority;
duplicates and logically old receipts do not change registry state, while the
existing pipeline still publishes non-retained QoS 1 `edge.time` for every
valid receipt. A delayed LWT cannot replace an active valid sleep window, and
an older-generation LWT cannot regress a newer wake.

SQLite now persists the declared mode, relative interval, announcement receipt,
wake/deadline timestamps, and missed-wake count. REST exposes `power_mode`,
`wake_interval_seconds`, `expected_wake_at`, connectivity, and the count.
`devices_sleeping` and `device_wake_missed_total` are fleet-wide unlabeled
metrics; sleeping devices are excluded from the offline gauge. Measurement
staleness remains a separate Edge-receipt-time calculation and uses the battery
wake interval as its effective cadence.

Tests cover intentional sleep, duplicate sleep without `last_seen_at` refresh,
unexpected disconnect, timer-only missed wake, wake recovery, delayed LWT,
old-status ordering, conservative unknown mode, invalid/unbounded sleep, and
always-on compatibility. The live-Mosquitto integration additionally proves
that both the accepted announcement and its transport duplicate receive a
fresh, non-retained `edge.time` response.

The correction gate passed formatting, warnings-as-errors Clippy, the complete
all-features workspace suite, the required `RHIZO_REQUIRE_BROKER=1` suite
against live Mosquitto (including broker restart), both Thumb no-std builds,
SQLx prepare/check after applying all six migrations, docscheck (6,465 checks),
and `git diff --check`. Compose configuration was already demonstrated by the
original M4 gate and the Compose file is unchanged by this correction; the
literal re-check could not execute on this host because its `docker.cmd` wrapper
targets an absent `Ubuntu-24.04` WSL distribution. The running workspace
`edge-controller.exe` was stopped once because Windows held its output binary
open and blocked the requested Cargo gate.

Planning was reconciled without starting M5: M5-020 is superseded by this
correction; the minimal status portion of M5-019 is superseded while its battery
measurement/config remainder stays ready. M5-021 still owns simulator sleep.
M6-022/-023 retain durable pending-until-wake command intent delivery and forbid
retained water commands; M9-019…021 retain actual deep sleep, gated peripheral
power, and wake/publish/sleep firmware; M10-011/-012 retain measured sensor
stabilisation and system power draw; M12-018 retains “Sleeping — expected wake”
and “Pending until device wakes”; M14-009 retains optional solar/energy planning.

Final state remains: **M4 DONE · M5 READY · M5 not started**.
